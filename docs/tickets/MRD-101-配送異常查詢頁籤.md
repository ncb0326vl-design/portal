# MRD-101　［託運查詢］新增「配送異常」查詢頁籤

| 項目 | 內容 |
| --- | --- |
| 類型 | Feature |
| 優先級 | P2 |
| 需求來源 | 客服部門 |
| 相關頁面 | 託運管理 > 託運查詢 > 託運單查詢 |
| 預估 | 1 人日 |

## 背景

客服部門每天要回覆客戶「我的貨為什麼還沒到」的詢問。目前「託運單明細」頁籤雖然可以用「異常」狀態篩選出有問題的託運單，但結果表格沒有顯示異常原因，客服還要再去後台系統一筆一筆查，很花時間。

客戶端也希望能自己看到異常原因，並且可以只看某一種異常（例如只看「收件人拒收」的單子，方便業務追聯絡）。

## 需求內容

在「託運單查詢」頁面新增第三個頁籤「配送異常」，與現有的「託運單明細」、「請款彙總」並列。

### 查詢條件

| 欄位 | 型態 | 必填 | 說明 |
| --- | --- | --- | --- |
| 客戶 | 下拉選單 | Y | 同現有頁籤 |
| 託運帳號 | 下拉選單 | Y | 需依所選客戶連動 |
| 出貨日期 | 日期區間 | Y | 區間上限 92 天，迄日不可早於起日 |
| 異常原因 | 下拉選單 | N | 預設「全部」 |

「異常原因」的選項如下，請放在 `Constants/defaultValues.js`：

- 收件人地址不符
- 溫層異常
- 包裝破損
- 道路中斷延誤
- 收件人拒收

### 查詢結果欄位

託運單號、出貨日期、託運帳號、目的地、運費(TWD)、異常原因

- 運費須靠右對齊並加上千分位（同「託運單明細」）。
- 需提供「匯出 CSV」按鈕，檔名為「配送異常」。
- 查無資料時顯示現有的無資料畫面。

## 驗收條件

1. 頁籤順序為「託運單明細」、「請款彙總」、「配送異常」。
2. 未選客戶時，「託運帳號」為 disabled；選擇客戶後才可選，且只出現該客戶的帳號。
3. 必填欄位未填就按「查詢」，欄位下方顯示錯誤訊息且不送出查詢。
4. 日期區間超過 92 天時顯示錯誤訊息。
5. 「異常原因」留「全部」時，回傳該期間內所有異常單；指定某一原因時只回傳該原因的資料。
6. 查詢結果可正確匯出 CSV，且中文在 Excel 開啟不會亂碼。

## 技術備註

- 後端 API `POST /shipment/getShipmentException` 尚在開發中，**本機請沿用現有 saga 的 `IS_DEV_ENV` fake data 寫法**（可參考 `src/redux/logistics/shipmentQuery/shipmentInquiry/saga.js`），先讓畫面跑得起來即可。
- 預計的 request / response 欄位命名比照現有 API 的 snake case 風格（例如 `excreason`），前端轉為 camelCase 後使用。
